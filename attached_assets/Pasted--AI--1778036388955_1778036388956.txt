一、图片搜索：从"屏蔽坏结果"升级为"主动发现好结果"
当前状态的体验缺口
你现在做的是事后过滤（搜出来再屏蔽坏的），但用户真正的痛点是搜不到对的。当用户搜"AI主播 信任 购买意愿"的概念模型图时，通用图片搜索引擎的索引里根本就没几张相关的学术图。黑名单只解决"结果里有垃圾"，不解决"结果太 sparse"。
深度优化建议
1.1 新增"从用户已添加论文中提取图表"功能（体验飞跃）
这是最直接解决"搜不到"的手段。用户项目里已有的论文，本身就是最相关的图库。
具体实现路径：
在论文添加流程中（OpenAlex导入或PDF上传后），增加一个异步图表提取任务：
对OpenAlex论文：如果 primary_location.pdf_url 存在，下载PDF后用 pdf2pic/pdfjs 将每页渲染为图片
对用户上传的PDF：直接处理已有文件
用GPT-4V或轻量级图像分类模型（如ResNet+自定义分类头）筛选出"包含方框和箭头的页面"
将提取到的图表页保存到 paper_figures 表：
TypeScript
复制
paper_figures: {
  id, paperId, pageNumber, imageUrl, 
  figureType: "conceptual_model"|"sem_path"|"framework"|"methodology"|"other",
  extractedAt, aiConfidence
}
图片搜索UI新增一个数据源切换器：
"从我的论文中提取"（默认）→ 只搜索用户项目内论文的图表
"从学术网络搜索" → 现有SerpApi/Brave逻辑
这样用户的搜索体验从"大海捞针"变成"从我已经验证过的论文里找图"
1.2 增加"图-论文"关联的Hover预览（体验细节）
当用户看到一张搜索结果的缩略图时，现在的体验是：点进去看原网页。更好的体验：
Hover卡片：鼠标悬停在图片上时，显示：
这张图片来自哪篇论文（作者，年份，标题）
该论文的引用次数
该论文中被提取的关键变量列表
"查看论文模型" 快速跳转按钮
点击图片后的侧边栏：不是直接跳外链，而是在右侧滑出面板：
大图预览
论文基本信息 + OpenAlex链接
该论文提取出的变量列表（如果有）
"将这张图的变量加入我的项目" 按钮（一键导入）
1.3 图片搜索结果增加"为什么推荐"的解释（建立信任）
当前AI筛选只返回一个 category badge（如"✓ SEM路径图"），用户不知道为什么这张图和他的研究相关。
建议在每张图片卡片底部增加一小行解释文字（由AI生成，限制30字）：
"来自2023年关于AI主播信任的论文，包含心流体验→购买意愿的中介路径"
实现方式：在 aiRelevanceFilter 函数中，让AI不只返回 keep: [{i, category}]，还返回一句话理由：
JSON
复制
{"keep":[{"i":0,"category":"conceptual_model","why":"与您项目中的'perceived trust'和'purchase intention'变量直接匹配"}]}
1.4 增加图片的"学术质量评分"排序维度
当前的排序只基于 _score（关键词匹配+学术域名加分）。建议增加一个综合质量分：
TypeScript
复制
interface ImageQualityScore {
  citationScore: number;      // 来源论文的被引次数（从OpenAlex获取）

这样用户看到的排序不只是"关键词匹配度高"，而是"这张图来自一篇高被引的近期论文，且图片清晰"。
二、模型组合：从"AI自由创作+后验规则过滤"升级为"数据驱动推荐+结构化填空"
当前状态的体验缺口
你现在的方式是：把所有变量和理论骨架扔给AI → AI自由组合 → 后验验证器过滤不符合规则的。这个流程的问题是：
AI经常会生成被验证器拒绝的模型（你代码里就有 rejected 数组专门收集这些）
用户看到的生成过程是黑盒的——不知道AI为什么这么连
没有利用"变量关系的历史数据库"——如果100篇论文都验证过 A→B，那这个边应该是"强推荐"，而不是让AI每次重新判断
深度优化建议
2.1 构建"跨论文变量关系图谱"（核心数据基础设施）
这是从"AI乱连"到"数据驱动推荐"的关键转变。在现有 paperHypothesesTable 的基础上，构建一个聚合视图：
新增 construct_relationships 物化视图/表：
sql
复制
-- 聚合所有论文中提取的假设，形成全局变量关系知识库
CREATE TABLE construct_relationships AS
SELECT 
  canonicalFrom,           -- 标准化后的源变量名
  canonicalTo,             -- 标准化后的目标变量名
  relationshipType,        -- positive|negative|moderates|mediates
  supportingPapers,        -- 支持这条关系的论文ID数组
  supportingHypotheses,    -- 对应的假设ID数组
  totalOccurrences,        -- 出现次数
  avgEffectSize,           -- 平均效应量（如果有）
  primaryDomains,          -- 主要出现在哪些研究领域
  earliestYear,            -- 最早验证年份
  latestYear               -- 最新验证年份
FROM paper_hypotheses
GROUP BY canonicalFrom, canonicalTo, relationshipType;
前端体验：
在变量图谱页面，边的粗细/颜色由 totalOccurrences 决定：
粗边 = 多篇论文验证过（强证据）
细边 = 只有1篇论文（弱证据）
红色边 = moderator关系
蓝色边 = mediator关系
Hover边时显示："这条关系在N篇论文中被验证，最新来自Author(Year)"
2.2 模型生成改为"推荐候选 + AI填空"模式
现有流程：AI从零创作整个模型 → 验证器过滤
优化流程：
系统层先计算出"合法的候选边集"（算法驱动，确定性强）：
从 construct_relationships 中筛选出：两端变量都在当前session的变量池中的边
应用 layerIndex 过滤：只允许从低层指向高层的边
应用 sharedVariables 过滤：标记可作为EXTEND连接点的共享变量
应用操作符约束：为每个操作符生成一组"合法变量组合"
输出：候选边列表（每条边标注：支持论文数、效应量、是否来自formal hypothesis）
将候选边集注入AI prompt，让AI在这个"已经合法的菜单"里选择和组合：
plain
复制
CANDIDATE EDGE POOL (system-validated, you MUST pick from this list):
- A→B [supported by 3 papers: P1(H1), P3(H2), P5(H4)] [layer: cognitive→affective]
- B→C [supported by 2 papers: P2(H1a), P4(H3)] [layer: affective→intention]
- M moderates A→B [supported by 1 paper: P6(H5)] [justification provided]
AI的任务从"创作"变成"组合设计"，大幅降低被拒绝率
前端体验：
生成模型前，用户可以先看到"可用的关系池"——一张大网，蓝线是多篇论文支持的强关系，灰线是弱关系
用户可以点击"希望包含这条关系"来引导AI生成
2.3 增加"操作符预览"功能（让生成过程透明）
现在的操作符（EXTEND/INSERT_MODERATOR等）对用户来说是个黑盒概念。建议：
在生成页面，每个操作符做成一个可展开的卡片：
显示操作符的定义 + 一个mini示例图（用简单的SVG动画展示"这个操作符做什么"）
显示在当前项目中，这个操作符可以应用到哪些变量组合上
示例："EXTEND: 检测到P1的perceived usefulness→attitude可以和P3的attitude→behavioral intention连接（共享变量：attitude）"
用户勾选"使用EXTEND"后，系统高亮显示图中哪些边会被EXTEND影响
2.4 增加"模型合理性检查面板"（生成后）
模型生成后，不只是显示模型图，还要显示一个质量评分面板：
TypeScript
复制
interface ModelQualityReport {
  structuralScore: number;      // 结构是否符合经典骨架（0-100）
  evidenceScore: number;        // 有多少条边有论文支持（0-100）
  noveltyScore: number;         // 跨论文组合的新颖程度（0-100）
  layerCompliance: boolean;     // 是否遵守construct layer顺序
  duplicateRoleCheck: boolean;  // 是否有变量同时做med+mod
  moderatorJustified: boolean;  // 所有调节变量都有解释
  weakEdges: Array<{            // 需要用户注意的边
    edge: {from, to},
    warning: "这条关系仅来自1篇论文，建议补充文献"
  }>;
}
前端展示：用雷达图展示三个分数，用✓/✗清单展示检查项，用黄色高亮显示weakEdges。

3.2 模型图本身增加"证据可视化编码"
不用等用户点击，图上的边本身就编码证据强度：
边的粗细：支持论文越多 → 边越粗
边的颜色：
深绿色 = 有formal hypothesis + effect size
浅绿色 = 有论文引用但无formal hypothesis
橙色 = AI推断/仅有1篇弱支持
红色虚线 = 缺少文献支持（需要用户补充）
边的标签：hover时显示 "H2a (β=.42)" 或 "3 papers"
3.3 自动生成"模型文献综述段落"
对生成的新模型，AI自动生成一段可以直接放进论文的文献综述文字：
"本研究模型整合了三个理论视角。首先，基于SOR理论（Mehrabian & Russell, 1974），我们将直播环境特征视为刺激变量。其次，参照Wang & Liu (2023) 的发现，感知信任对购买意愿的正向影响（β=.42, p<.001）被引入为主效应。最后，通过JD-R模型的资源路径（Bakker & Demerouti, 2007），我们将主播互动性作为工作资源纳入模型..."
这段文字自动：
引用所有涉及的骨架理论（带原始作者和年份）
对每条边标注来源论文和假设编号
说明操作符的应用逻辑（"通过EXTEND操作将P1的A→B与P2的B→C连接"）
输出为可复制到Word的格式（带APA引用）
