3. 这次实现还需要注意的点
3.1 缓存 key 必须足够精确
ai-review / generate-contribution 缓存不能只按 modelId。

至少要包含：

sessionId
modelId
model.updatedAt 或 model hash
innovationMeta.computedAt / landscapeVersion
language
prompt/options
否则会出现：

用户改了模型，但拿到旧 review / 旧 contribution。

建议 cache key：

`${sessionId}:${modelId}:${modelUpdatedAt}:${landscapeVersion}:${lang}:${optionHash}`
3.2 in-memory cache 可以接受，但要说明限制
30 分钟内存缓存可以先用，但要知道：

服务重启会丢
多实例不共享
不能当可靠缓存
不适合长期审计
第一版可以接受，后面高频后再落 DB。

3.3 积分标签不要只静态写死
静态 ≈N 积分 可以先用，但最好下一步变成：

基于模型、输入长度、最大输出 token 的估算
否则用户会看到估算和实际差很多。

建议用函数：

estimateCredits(route, model, estimatedPromptTokens, maxCompletionTokens)
3.4 refine-contribution 是否也要缓存？
你们说 refine 成功清 cache，这是对的。

但 refine 本身如果同样输入重复点，也可能重复花钱。建议也加短缓存或按钮防抖：

同一 model + 同一 instruction 10 分钟内不重复 refine
