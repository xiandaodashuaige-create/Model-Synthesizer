一、模型图片/参考图搜索优化建议
当前主要问题
搜索源太少

主文献搜索主要依赖 OpenAlex。
图片搜索依赖 SerpAPI/Brave 的图片索引，不是真正的“论文模型图数据库”。
当前 PUBLISHER_SITE_FILTER 只覆盖 ResearchGate、ScienceDirect、Springer、Wiley、Taylor & Francis、Emerald、SAGE、Frontiers、MDPI、PMC 等少数站点。
筛选依赖标题/域名，不够理解图片内容

AI relevance gate 主要看到候选的 title 和 sourceDomain，没有真正读取图片里的变量、箭头、图注、论文上下文。
所以容易搜到“像模型图但主题不对”的结果。
session 主题没有真正接入图片搜索上下文

loadSessionImageCtx() 里 topic: null，目前主要只用变量名和论文标题，缺少用户创建 session 时填写的研究主题。
前端筛选能力弱

没有领域、年份、方法、模型类型、变量匹配度、是否有图、是否开放 PDF 等过滤器。
收藏的参考资料存在 localStorage，不进入数据库，后续不能系统化用于模型生成依据。
建议改造
1. 扩大“文献 + 模型图”检索来源
建议把搜索拆成多个 source lane：

免费/开放优先：
OpenAlex
Semantic Scholar
Crossref
CORE
Europe PMC
PubMed / PMC
arXiv
DOAJ
Unpaywall
可选增强：
SerpAPI Google Scholar / Google Images
Lens.org
Dimensions / Scopus / Web of Science 如果以后有授权
不要只做图片搜索，而是做：

先找高相关论文 → 拉取 OA PDF/HTML → 抽取 Figure 和 Caption → 判断是否是 conceptual model / SEM / framework。

这样比直接搜索网页图片稳定得多。

2. 建立“模型图候选库”
建议新增结构化对象：

paperId
figureUrl / thumbnailUrl
figureNumber，例如 Fig. 1
caption
page
sourceUrl
extractedText/OCR
detectedConstructs
figureType：conceptual_model / sem_path / framework / process_flow / other
topicRelevanceScore
constructOverlapScore
confidence
这样系统不再只是“搜图片”，而是逐步积累自己的“研究模型图数据库”。

3. 强化筛选评分
建议每个结果给出综合评分：

总分 =
主题相似度
+ 变量重合度
+ 图像类型置信度
+ 论文质量分
+ 是否有可访问全文/PDF
+ 是否包含 hypothesis/model/framework/SEM 等信号
- 噪音惩罚
并在界面展示：

为什么匹配？
匹配了哪些变量？
哪些变量没有匹配？
是概念模型、SEM 路径图还是理论框架？
推荐程度：高/中/低
4. 加用户反馈学习
用户应该能对搜索结果标记：

相关
不相关
主题对但不是模型图
是模型图但变量不对
领域不对
方法不对
这些反馈进入数据库，后续用于调整筛选规则和 query expansion。

二、模型组合逻辑优化建议
当前主要问题
变量关系容易被“角色组合”误导

variable-graph 里会按类型自动连：
independent → mediator
independent → dependent
mediator → dependent
这只是启发式，不等于论文真实假设关系。
模型生成靠 prompt 约束，但程序校验不够强

当前生成 prompt 已经要求操作符、理论骨架、至少 3 篇论文、证据引用。
但 validator 主要检查：
节点数
边数
来源论文数
evidenceCitationText 非空
没有严格验证：
IV/Mediator/Moderator/DV 的角色语法
moderator 到底调节哪一条路径
evidence 是否真的支持该边
这条边是否来自历史模型或理论类比
调节变量表达不够学术化

现在 edge 是 fromVariableId → toVariableId。
但调节变量在论文中通常不是简单 M → Y，而是：
Moderator M moderates the relationship between X and Y
也就是调节的是“一条关系”，不是单纯指向一个变量。

强制“两个操作符 + 三篇论文”可能导致硬拼
如果材料不够，系统仍倾向生成模型。
更适合让系统判断“证据不足，需要补充哪些文献”。
建议改造
1. 建立“历史关系知识图谱”
不要只存变量，要存论文真实关系：

Paper A:
Trust → Purchase Intention
Evidence: H1 / 原文句子 / 页码 / 图号
Role: hypothesized / tested
Sign: positive
Method: SEM
建议新增或抽象出：

constructs / variables
construct aliases
extracted_relations
relation_evidence
paper_models
theory_backbone_matches
每条关系都应该是知识图谱的一条边，而不是生成时临时猜。

2. 做变量标准化与同义词归并
现在变量按字符串 name 匹配，容易出现：

trust
perceived trust
consumer trust
trust in AI streamer
建议引入 construct canonicalization：

canonicalConstruct: Trust
aliases:
- perceived trust
- consumer trust
- trust in AI anchor
context:
- live commerce
- AI streamer
roleHistory:
- mediator in P1
- independent in P3
- dependent in P7
这样模型组合时能知道一个变量在历史研究中常见角色是什么。

3. 增加“模型语法 validator”
建议在生成后增加程序化校验：

dependent 不能指向 independent
mediator 必须处于 X → M → Y 路径中
moderator 必须绑定到一条 base edge：moderatesEdgeId
同一个模型不能出现无解释的循环
每条边必须有：
direct evidence，或
analogy evidence，或
theory backbone evidence
如果是类比关系，必须说明类比依据
建议把边关系分为三类：

direct: 论文中明确出现过这条关系
analogical: 历史关系中存在相似构念关系，当前做理论类比
theory_graft: 来自 TAM/SOR/TPB/UTAUT 等经典理论骨架
4. 把生成过程改成多阶段
不要让 LLM 一步生成完整模型。建议流程：

识别研究目标

研究主题
目标因变量
研究情境
目标理论视角
检索候选历史关系

找与目标因变量相关的历史路径
找常见前因变量
找常见中介
找常见调节
选择理论骨架

S-O-R
TAM
TPB
UTAUT
ELM
Parasocial
Trust Transfer
Flow
组装候选模型

串联中介
并联中介
调节中介
理论嫁接
规则校验

角色顺序
证据完整性
历史合理性
变量兼容性
LLM 复审

让 AI 作为 reviewer 判断是否像一篇论文里的模型，而不是乱拼图。
5. 当证据不足时不要硬生成
建议加一个“材料充分性检查”：

当前文献不足以支持：
- X → M
- M → Y
- W moderates X → Y
建议补充搜索：
- AI streamer trust purchase intention SEM
- virtual influencer parasocial interaction purchase intention
这比强行生成一个看起来完整但没有论文依据的模型更符合博士论文研究场景。
